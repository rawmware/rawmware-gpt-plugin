# v2.1 performance review: 2026-10-02

**Question:** Is the operator actually powerful and useful for developers, or does it just look that way?

## Answer
v2.0 had real defects and gaps. v2.1 fixes them and refocuses every tool on the jobs that block developers: red CI, failed deploys, PR review, dependency risk, stale library knowledge, live-site problems.

## Defects found (and fixed)
- **Security:** `vercel` used the owner's token for any caller (public could list owner projects/logs/env keys). Now requires the caller's token.
- **Security:** SSRF bypass via IPv4-mapped IPv6: the URL parser normalizes `[::ffff:127.0.0.1]` to `[::ffff:7f00:1]`, which the guard didn't decode.
- **Security:** auth headers were forwarded across redirect origins (breaks GitHub log downloads; leaks tokens to third parties).
- **Correctness:** HTML→text collapsed whitespace inside `<pre>`: scraped code lost indentation. Now fenced verbatim; tables kept.
- **Reliability:** single keyless search provider (often blocked from cloud IPs) → provider chain. No global deadline → composite tools now share a time budget and return partial results.
- **Usefulness:** all GitHub calls used the server token: no private repos, writes owner-only. Now GitHub OAuth (GPT) / headers (MCP) act as the user; cache partitioned per identity.

## Added
`github` grep / pr / compare / run_logs / issue / batch files / ETag revalidation · `github_write` PR iteration + reviews · `deps` (OSV + npm/PyPI/crates/Go) · `libdocs` (Context7 → llms.txt → docs) · `site` health / crawl / design.

## Removed
`about`, `feedback`, launch/portfolio playbooks: self-promotion that cost tokens every turn and helped no user.

## Evidence
- 37 offline tests (mocked fetch) cover each behavior above, including the SSRF and cache-isolation cases.
- Live from the dev container: npm + PyPI lookups returned current versions (react 19.3.0, requests 2.34.2; next 14.0.0 flagged 3 majors behind 16.3.x). GitHub anonymous quota exhaustion was detected from live headers and surfaced with the fix. OSV/Context7/search hosts were egress-blocked there, and the tools degraded with explicit errors.

## Unknowns
- End-to-end OAuth with ChatGPT needs a real GPT + GitHub OAuth app to verify (proxy endpoint is implemented to the OAuth spec).
- OSV, Context7, DuckDuckGo and Vercel calls are verified against mocks of their documented formats, not live, until deployed.
